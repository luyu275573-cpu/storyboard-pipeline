# M2 开发验收记录

日期：2026-09-26。继续使用 FastAPI/SQLAlchemy/MySQL、Redis 与 React/TypeScript，无新增依赖，无真实付费模型调用。

## 交付范围

1. 项目/类型/镜头三级预算在同一短事务中预留；按实际费用结算、释放差额。失败但已计费的结果也记账。数据库 CHECK 约束防止负数或占用超过预算。
2. 新增 provider_requests 表；api_call_logs 逐次保存报价、预留、供应商幂等键、任务号、状态和报账金额。成功或失败请求重放都返回原结果，相同操作标识改参数返回冲突。
3. 超时、取消、进程退出的模糊窗口及续租失败保留额度；reconcile 只查询旧请求，未知结果不触发降级/重发。并发对账只结算一次。
4. 供应商按能力及名称路由。只有明确未受理、未计费的拒绝或已知终态失败才进入后备供应商；同一供应商不自动重试。
5. Redis 按持有者令牌续租，旧持有者不能释放或续租新持有者的额度。长任务不再受固定 60 秒计数器限制。
6. 预算页显示已花费、预留、可用余额与调用明细；进入页面重新获取数据。调用列表提供分页，API 可按能力/供应商/成功状态筛选；未决调用不算明确失败。

供应商报账超过报价时保留原报账金额和预留，冻结项目新调用。预算上界保证依赖适配器提供正确的远端计费上界；不能用本地数据库阻止供应商错误计费。争议的人工处理入口与真实价格验证留到供应商接入阶段。
