# 01 · 架构设计

## 1. 设计目标与约束

**目标**：把漫剧生产中"抽卡 → 人工筛选 → 重抽"这个黑盒循环，变成可编程、可度量、可回归的工程系统。

**硬约束**（决定了架构形态，不是选择偏好）：

| 约束 | 来源 | 对架构的影响 |
| --- | --- | --- |
| 显存 6GB（RTX 2060） | 本机硬件 | 不跑本地生成模型，图像/视频全部走云 API |
| 预算 200 元 | 用户设定 | 质检战场放图像层；必须有预算熔断与成本记账 |
| 周期 1-2 周 | 用户设定 | 只做流水线与质检层，不做完整创作平台 |
| 视频生成分钟级耗时 | 云 API 特性 | 必须异步任务队列 + 状态机 + SSE 进度推送 |
| 抽卡成功率行业仅 15% | 行业数据 | 重试与降级是主路径，不是异常分支 |

**一条贯穿全局的设计原则**：沿用农牧项目验证过的 AI 安全范式——
**不把模型输出当作可信结果，在应用层重新判定**。
农牧项目里是"不把 Prompt 当安全边界，后端重做角色校验"；
本项目里是"不把生成图当合格帧，质检层重做判定"。同一套思路，两个业务域。

## 3. 数据流：一次完整的流水线运行

```
用户上传剧本 / 小说片段
   │
   ▼
[1] 剧本解析         LLM → 场景切分、角色抽取、台词归集
   │                 产出：Scene[] + Character[]（结构化 JSON）
   ▼
[2] 角色建档         人工确认或补全角色特征库（三级锚定的第 1 级）
   │                 ⛳ 人机关卡 A：角色设定确认（不可跳过）
   ▼
[3] 分镜生成         分镜 Agent（LangGraph）
   │                 LLM → Shot[]：景别、构图、角色、动作、台词、时长、运镜
   │                 ⛳ 人机关卡 B：分镜脚本审核（可编辑后放行）
   ▼
[4] 关键帧抽卡       角色锚定组装 Prompt → 图像 Provider 批量生成
   │                 每镜头抽 N 张（N 由预算与策略决定）
   ▼
[5] 质检判定 ★核心   质检 Agent：多模态视觉模型逐张判定
   │                 ├─ 合格 → 进入 [7]
   │                 ├─ 可修复 → 局部重绘 / 换种子重抽 → 回 [4]
   │                 └─ 人设漂移 → 回 [2] 检查锚定强度
   │                 每轮记账：调用次数、花费、判定结果
   │                 ⛳ 熔断：镜头重试超上限 或 预算余额不足 → 挂起待人工
   ▼
[6] 人工终审         ⛳ 人机关卡 C：先审后播合规审核（强制）
   │                 质检 Agent 只给建议，最终放行权在人
   ▼
[7] 视频生成         图生视频 Provider（少量调用，链路验证）
   │                 异步任务，分钟级，SSE 推进度
   ▼
[8] 合成导出         FFmpeg 按时间轴拼接 + 转场 + 导出
   │                 产出：成片 + 逐镜头成本报表 + 抽卡成功率统计
   ▼
[9] 数据沉淀         本次运行的抽卡/判定/成本数据入标注集，反哺质检校准
```

**四个不可跳过的人机关卡**（A 角色确认、B 分镜审核、C 合规终审，加上质检挂起时的人工介入）
是刻意设计的：既对应监管要求的"先审后播"，也让"AI 生成、人确认、系统落账"这条
你在农牧项目已经验证过的范式在内容生产域复用。

## 4. 关键模块职责

### 4.1 Provider 适配层（`app/providers/`）

统一抽象，屏蔽供应商差异。所有调用必须经过它，**不允许业务代码直接发 HTTP 请求**——
这是成本记账和降级能生效的前提。

```
BaseProvider
├── generate()      统一入口，内部完成：限流 → 调用 → 重试 → 记账
├── 子类：ImageProvider / VideoProvider / VisionProvider / LLMProvider
└── ProviderRouter  按镜头类型与供应商健康度选路，失败自动降级
```

每个 Provider 必须实现：
- **幂等键**：`(shot_id, attempt_no, model, seed)` → 防止重试造成重复扣费
- **调用记账**：无论成败都写 `api_call_logs`（成功记花费，失败记原因）
- **限流退避**：指数退避 + 供应商级并发闸门（云 API 普遍限制并发为 1-2）
- **降级链**：首选 → 备选 → 挂起待人工，不静默失败

### 4.2 质检 Agent（`app/agents/qc_agent.py`）★核心卖点

判定维度（对齐行业六大维度，图像层可判定的取前四类）：

| 维度 | 判定内容 | 处置 |
| --- | --- | --- |
| 五官畸形 | 眼鼻嘴错位、多指、肢体扭曲 | 换种子重抽 |
| 人设漂移 | 与角色特征库比对：脸型/发型/服饰/配色 | 提升锚定强度后重抽 |
| 色彩断层 | 与同场景已合格帧的色调一致性 | 局部重绘或调色 |
| 构图合规 | 景别是否符合分镜要求、主体是否出画 | 重抽并强化构图约束 |
| 内容合规 | 违规元素（对应"先审后播"） | 强制拦截，转人工 |

输出**结构化判定**而非自然语言：`{pass: bool, dimensions: {...}, severity, suggestion, confidence}`。
判定结果必须可复现、可回归——这是它能被黄金测试集校准的前提。

详见 `docs/03-质检Agent与评估.md`。

### 4.3 角色锚定（`app/knowledge/`）

三级锚定体系，详见 `docs/04-角色一致性锚定.md`：
1. **全局特征库固化**：角色档案（脸型/眼距/发型/服饰/配色/性格表情）存库，每次生成复用固定描述，禁用"清秀""帅气"等主观词
2. **参考图主体绑定**：基准图 + 供应商的主体参考能力（Vidu 参考生图 / 即梦智能参考）
3. **时序特征递延**：同场景镜头集中生成、上一合格帧作为下一镜头的参考输入

### 4.4 流水线状态机（`app/pipeline/`）

LangGraph 状态图，状态持久化到 Redis + MySQL，支持：
- **断点续跑**：进程重启后从最后完成的节点继续，不重复扣费
- **循环重试**：抽卡 ↔ 质检 之间的环，带最大轮次
- **预算熔断**：每轮前检查预算余额与镜头重试次数
- **部分结果保留**：中断时已合格的帧不丢弃

### 4.5 成本审计（`app/services/cost_service.py`）

逐次调用记账，能回答：
- 这个镜头抽了几次卡、花了多少钱、第几次合格
- 这次运行的总花费、单分钟成片成本
- 质检 Agent 拦下了多少次无效重抽（= 省了多少钱）
- 各供应商的成功率与单价对比（为路由策略提供数据）

**这是简历上量化指标的唯一数据来源，必须在第一周就打通，不能留到最后。**

## 5. 异步与并发模型

```
FastAPI (async)  ──投递──▶  ARQ Worker (async)
      │                          │
      │                          ├─ 调用 Provider（async HTTP，等待云端渲染）
      │                          ├─ 写进度到 Redis
      │                          └─ 写状态与账目到 MySQL
      └──SSE 订阅 Redis 进度──▶ 前端实时展示
```

**关键约束**：
- `async def` 路由/任务里**禁止调用同步阻塞库**（同步 MySQL 驱动、requests）——
  会卡死事件循环，并发直接归零。数据库用 `aiomysql` / `asyncmy`，HTTP 用 `httpx.AsyncClient`。
- 视频生成是分钟级任务，必须设**分层超时**：单次请求超时 < 任务总超时 < 前端等待超时，
  配合取消令牌，避免僵尸任务持续扣费。
- 供应商并发闸门：多数图像/视频 API 免费或低配档并发限制为 1-2，用 Redis 信号量控制，
  超限排队而非直接失败。

## 6. 部署架构（腾讯云）

```
                    ┌──────────────┐
   公网 HTTPS ─────▶│    Nginx     │  反向代理 / 静态资源 / SSE 不缓冲
                    └──────┬───────┘
                           │
              ┌────────────┴────────────┐
              ▼                         ▼
      ┌───────────────┐        ┌────────────────┐
      │ FastAPI 服务   │        │  ARQ Worker    │
      │ (systemd)     │        │  (systemd)     │
      └───────┬───────┘        └────────┬───────┘
              │                         │
              └────────┬────────────────┘
                       ▼
        ┌──────────────────────────────┐
        │  MySQL 8   │   Redis         │
        └──────────────────────────────┘
                       │
                       ▼
              本地 storage/（关键帧、片段、成片）
```

复用农牧项目已验证的部署范式：`nginx.conf` + systemd unit + `install.sh` + `RELEASE_CHECKLIST.md`。

**SSE 必须关缓冲**（`proxy_buffering off`），否则进度推送会被 Nginx 攒着不发——
这是农牧项目踩过的坑，直接沿用结论。

## 7. 与农牧项目的架构同构性（面试主线）

| 维度 | 农牧系统 | 分镜流水线 |
| --- | --- | --- |
| 链路 | 自然语言 → Tool Calling → 草稿预览 → 人工确认 → 正式过账 | 剧本 → 分镜 → 草稿帧 → 质检/人工确认 → 渲染合成 |
| 不可信边界 | 不把 Prompt 当安全边界，后端重做角色校验 | 不把模型输出当合格帧，质检层重做判定 |
| 幂等 | 一次性 nonce、重复确认幂等 | 调用幂等键，防重试重复扣费 |
| 并发控制 | 数据库行锁、单据版本校验 | 供应商并发闸门、镜头版本快照 |
| 人机协同 | 草稿 → 人工确认 → 过账 | 三道强制人工关卡（角色/分镜/合规） |
| 可追溯 | 审计日志、移动平均成本 | 逐次调用记账、抽卡成功率统计 |
| 部署 | Waitress + Nginx + systemd | uvicorn + Nginx + systemd + ARQ Worker |

一句话：**在两个完全不同的业务域里复用了同一套"AI 生成、系统判定、人工确认、全程记账"的受控写入范式。**
