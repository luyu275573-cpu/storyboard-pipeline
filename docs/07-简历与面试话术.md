### 项目描述（一句话定位，必须先撇清与竞品的关系）

> 面向 AI 漫剧工作室的**生产流水线调度与质量控制平台**，不做内容生成模型，
> 而是解决工业化生产中"黑盒抽卡、品质失控、成本不可见"三大痛点：
> 将「剧本 → 分镜 → 关键帧抽卡 → 质检 → 视频 → 合成」全链路编排为
> 可断点续跑、可预算熔断、可逐笔记账的自动化流水线。

**为什么必须先撇清**：面试官看到"漫剧平台"第一反应是"你和即梦/可灵/纳米漫剧流水线有什么区别"。
定位句里写清"不做生成模型，做流水线工程与质量控制层"，就把这个问题提前答了。

### 核心 bullet（按重要性排序，每条都要有数字）

1. **三级角色一致性锚定**：设计「全局特征库固化 → 参考图主体绑定 → 时序特征递延」三级体系，
   角色特征以结构化字段存储并**程序化拼装**为锚定 Prompt（禁用主观形容词、发色用色号、版本号可追溯），
   配合同场景集中生成策略，将主角跨镜头一次过合格率从盲抽基线 **X%** 提升至 **Y%**。

2. **质检 Agent 与自动重渲染闭环**：基于多模态视觉模型对关键帧做五官畸形、人设漂移、
   色彩断层、构图合规、内容合规五维判定，输出**结构化判定结果**（含漂移字段定位）驱动
   `换种子重抽 / 局部重绘 / 强化锚定` 三类自动修复；在 **N 张**人工标注黄金测试集上
   达到召回率 **X%**、误杀率 **Y%**，并按"漏放一张废片到视频层损失 1.4 元、
   误杀一张损失 0.25 元"的成本比刻意调保守阈值。

3. **成本可观测与预算熔断**：逐次 API 调用记账（含失败与限流），
   以**数据库原子条件更新**实现项目/镜头/类型三级预算熔断，并发下不超支；
   幂等键 `sha256(shot|attempt|model|seed)` + 唯一索引防 Worker 崩溃重启导致重复扣费；
   累计拦截 **N 次**无效生成，节省 **M 元**。

4. **LangGraph 流水线编排**：将九阶段生产链路建模为状态图，支持循环重试、
   条件路由、状态持久化与**断点续跑**（进程重启从最后完成节点继续，不重复扣费）；
   设置「角色确认 / 分镜审核 / 合规终审」三道**强制人机关卡**，
   落实 AIGC 动画"先审后播"监管要求，质检 Agent 只给建议、放行权在人。

5. **多供应商路由与降级**：统一 Provider 抽象屏蔽即梦/Vidu/可灵/百炼差异，
   按镜头类型选路（多角色同框走 Vidu 多主体绑定、动作镜头走可灵、
   低成本批量走即梦），配指数退避、供应商级并发信号量与失败降级链；
   路由策略基于 `api_call_logs` 实测的各供应商成功率与单价数据制定。

6. **异步长任务与实时进度**：视频生成为分钟级任务，采用 ARQ 异步队列 +
   分层超时（单次请求 < 任务总超时 < 前端等待）+ 取消令牌，避免僵尸任务持续扣费；
   SSE 推送逐镜头进度（Nginx 侧关闭 `proxy_buffering` 保证不被攒包）。

## 四、面试追问预案

### Q：你和即梦、可灵、纳米漫剧流水线有什么区别？

> 它们是做生成模型和 C 端创作工具的，我做的是**生产流水线的工程与质量控制层**。
> 打个比方，它们是"摄像机和画笔"，我是"制片管理系统"。
> 具体来说我解决三个它们不解决的问题：
> 一是抽卡的可度量性——我有黄金测试集和混淆矩阵，能算出每个维度的不合格率；
> 二是成本的可追溯性——逐次调用记账，能说出每个镜头抽了几次、花了多少钱；
> 三是流程的可控性——三道强制人机关卡和预算熔断，满足"先审后播"的监管要求。
> 而且我不绑定单一供应商，是按镜头类型路由的，即梦挂了能降级到可灵。

### Q：为什么质检放在图像层，不做视频质检？

> 两个原因。一是**判定可行性**：我要拦的五类问题里，五官畸形、人设漂移、色彩断层、
> 构图这四类在静态帧上就能判定，不需要视频；只有时序抖动必须看视频，而它占比小。
> 二是**成本效率**：图像单价约 0.25 元、视频约 1.4 元/5 秒，差 5.6 倍。
> 我的总预算只有 200 元，在图像层能跑上千次抽卡拿到有统计意义的成功率曲线，
> 在视频层只能跑一百多次，连置信区间都算不出来。
> 所以视频层我只做链路验证和一个样例片，把预算留给能产出数据的地方。

### Q：抽卡成功率提升多少？怎么测的？

> 【填真实数字】盲抽基线 X%，加三级锚定后 Y%，再加质检选择性重抽后 Z%。
> 测法是：同一批 20 个分镜描述、同一个主角，三轮各跑一次，统计一次过合格率。
> 基线那轮是完全不加锚定和质检的裸抽，100 张样本。
> 需要说明的是这个数据是**单角色、单画风**下的结果，换角色或换画风要重新标定，
> 我没有做跨画风的泛化验证——这是这个项目的局限。

**主动说出局限，比被问出来强得多。**

### Q：质检 Agent 的准确率怎么验证？

> 人工标注了 N 张黄金测试集，覆盖合格帧和各维度不合格类型，
> 算混淆矩阵得到召回率 X%、误杀率 Y%。
> 我刻意把阈值调保守，因为两类错误的成本不对称：
> 漏放一张废片到视频层损失 1.4 元，误杀一张只损失 0.25 元，差 5.6 倍。
> 所以宁可误杀不可漏放。
> 另外标注集本身是从正式抽卡的副产物里攒的，不额外花钱，
> 而且盲抽基线那 100 张里有大量不合格样本，正好是标注需要的。

### Q：角色一致性具体怎么做的？

> 三级。第一级是**特征库固化**：角色特征存成结构化字段——脸型、眼距、发色色号、
> 服饰款式与配色——然后**程序化拼装**成锚定 Prompt，不靠人手写。
> 因为人手写会不自觉换措辞，"黑色长发"这次写"及腰黑长直"、下次写"乌黑秀发"，
> 模型就当两个角色了。而且我禁用"清秀""帅气"这类主观词，只写可验证的客观特征，
> 发色直接用色号 #1A1A1A，因为"黑色"在厚涂画风下会偏棕偏蓝。
> 第二级是**参考图主体绑定**，多角色同框必须用支持多主体分别绑定的供应商（Vidu），
> 否则两个角色会互相污染特征——这是漫剧最常见的崩脸原因。
> 第三级是**时序特征递延**：同场景集中生成，上一合格帧作为下一镜头的参考输入，
> 保证场景内色调光照连续。
> 而且第三级和质检是联动的：质检返回 `drifted_fields: ["hair_color"]` 时，
> 下一轮只强化漂移的那个字段，不整体重写——锚定策略是被质检数据驱动的。

### Q：预算熔断怎么保证并发下不超支？

> 用数据库的原子条件更新，不是先查后写：
> `UPDATE budget_ledger SET spent = spent + :cost WHERE ... AND spent + :cost <= budget`，
> 影响行数为 0 就是预算不足，拒绝调用。
> 先查后写在并发下会超支，因为两个 Worker 可能同时读到"还有余额"。
> Redis 里另存一份热计数用于调用前快速拒绝，省一次 DB 往返，但 DB 是最终账本。
> 另外幂等键是 `sha256(shot|attempt|model|seed)` 加唯一索引，
> Worker 崩溃重启时不会对同一次抽卡重复调用 API——这条在调试期救过我，
> 因为视频生成是分钟级任务，中途崩了如果没有幂等，重启就是重复扣费。

### Q：这个项目和你农牧项目有什么关系？

> 架构上是同构的，我在两个完全不同的业务域复用了同一套范式。
> 农牧是「自然语言 → Tool Calling → 草稿预览 → 人工确认 → 正式过账」，
> 漫剧是「剧本 → 分镜 → 草稿帧 → 质检确认 → 渲染合成」。
> 共同的核心是**不信任模型输出，在应用层重新判定**：
> 农牧里是"不把 Prompt 当安全边界，后端重做角色校验"，
> 漫剧里是"不把生成图当合格帧，质检层重做判定"。
> 幂等、版本校验、人工关卡、全程审计这几件事在两个项目里都有对应实现，
> 只是农牧防的是越权和重复过账，漫剧防的是重复扣费和废片流入下游。
> 部署也是同一套：Nginx + systemd + 发布检查清单，SSE 关缓冲这个坑我在农牧踩过，漫剧直接沿用了结论。

### Q：这个项目的局限是什么？（大概率会问）

诚实答，这反而加分：

> 三个。一是**数据规模小**：我的黄金测试集只有 N 张、成功率数据是单角色单画风下的，
> 没有做跨画风泛化验证，行业要求是 200+ 组标注。
> 二是**质检只覆盖图像层**：时序抖动、物理错误这类视频层问题我只做了抽检，没有系统方案。
> 三是**没有真实用户**：是我自己按行业公开的生产流程设计的，
> 没有工作室实际用过，所以"好用"这件事我只能用数据说，不能用口碑说。
