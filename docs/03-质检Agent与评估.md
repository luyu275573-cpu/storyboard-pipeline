# 03 · 质检 Agent 与评估体系 ★核心

这一章是项目的差异化所在。做漫剧生成的人很多，**把质检做成可度量、可校准、可回归的工程系统**的人很少。

---

## 1. 为什么质检要放在图像层

| | 图像层质检 | 视频层质检 |
| --- | --- | --- |
| 单次调用成本 | 约 0.1-0.25 元/张 | 约 1.4 元/5 秒镜头 |
| 单次耗时 | 秒级 | 分钟级 |
| 200 元可跑次数 | **800-2000 次** | 约 140 次 |
| 统计意义 | 足够（可算成功率曲线、混淆矩阵） | 不足（样本太少） |
| 能判定的问题 | 五官畸形、人设漂移、色彩断层、构图 | 上述 + 时序抖动、物理错误 |

**结论**：质检要判定的主要问题（五官畸形、人设漂移、色彩断层）**在静态关键帧上即可判定**，
而抽卡成本的大头也浪费在图像返工上。把质检放图像层，是用 1/50 的成本拦住大部分废片。

视频层只做两件事：链路验证（证明端到端通）+ 时序抖动的少量抽检。

**面试话术**（被问"为什么不全链路质检"时）：
> 因为抽卡成本的绝大部分浪费在图像返工上，在图像层拦截是 ROI 最高的干预点。
> 我的预算约束反而逼出了这个决策：同样的钱，在图像层能跑上千次抽卡拿到统计意义上的成功率数据，
> 在视频层只能跑一百多次，连置信区间都算不出来。所以视频层我只做链路验证，把预算留给能产出数据的地方。

## 2. 判定维度与处置策略

对齐行业六大质检维度，取图像层可判定的部分：

| # | 维度 | 判定内容 | 不合格处置 | 是否可自动 |
| --- | --- | --- | --- | --- |
| 1 | 五官畸形 | 眼鼻嘴错位、多指少指、肢体扭曲、面部融化 | 换种子重抽（`reseed`） | ✅ |
| 2 | 人设漂移 | 与角色特征库逐项比对：脸型/眼距/发型/发色/服饰/配色 | 提升锚定强度后重抽（`strengthen_anchor`） | ✅ |
| 3 | 色彩断层 | 与同场景已合格帧的色调/光照一致性 | 局部重绘或调色（`redraw`） | ✅ |
| 4 | 构图合规 | 景别是否符合分镜要求、主体是否出画、留白是否够台词字幕 | 重抽并强化构图约束 | ✅ |
| 5 | 内容合规 | 违规元素、侵权风险（对应"先审后播"） | **强制拦截转人工**（`manual`） | ❌ 必须人工 |
| 6 | 时序抖动 | 帧间角色/场景跳变 | 视频层抽检 | 部分 |

**处置策略形成决策树**：

```
判定结果
├─ pass          → 进入人工终审关卡 C
├─ repairable    → 按 suggestion 分支
│   ├─ reseed              → 同 Prompt 换种子，回抽卡
│   ├─ redraw              → 局部重绘，回质检
│   └─ strengthen_anchor   → 提升锚定强度（加参考图权重/补特征词），回抽卡
├─ reject        → 重试计数 +1；超 max_retry → 挂起待人工
└─ blocked       → 合规拦截，立即挂起，禁止自动重试
```

**为什么合规维度不能自动放行**：2025 年 9 月《管理提示（动画微短剧管理）》已将 AIGC 动画
纳入分类分层审核、要求"先审后播"。质检 Agent 只能给建议，**放行权必须在人**——
这既是合规要求，也让"AI 生成、人确认、系统落账"的范式在内容域成立。

## 3. 判定输出：结构化，不是自然语言

视觉模型必须返回可解析的 JSON（用结构化输出/JSON mode，失败则重试并降级到文本解析）：

```json
{
  "pass": false,
  "verdict": "repairable",
  "confidence": 0.83,
  "dimensions": {
    "facial_deformity":   { "score": 0.12, "ok": true,  "note": "五官结构正常" },
    "identity_drift":     { "score": 0.71, "ok": false, "note": "发色由黑变棕，眼距偏大",
                            "drifted_fields": ["hair_color", "eye_distance"] },
    "color_discontinuity":{ "score": 0.24, "ok": true,  "note": "与同场景已合格帧色调一致" },
    "composition":        { "score": 0.18, "ok": true,  "note": "中景，主体居中" },
    "compliance":         { "score": 0.02, "ok": true,  "note": "无违规元素" }
  },
  "severity": "medium",
  "suggestion": "strengthen_anchor",
  "reasoning": "角色档案锁定黑发，本帧生成棕发，属人设漂移而非畸形，应强化发色锚定后重抽"
}
```

**必须结构化**的三个理由：
1. 可回归——同一张图跑两次，结果能比对
2. 可统计——各维度不合格率能算出来，指导锚定策略优化
3. 可校准——能和人工标注做混淆矩阵

`drifted_fields` 直接映射回 `characters` 表的特征字段，形成**闭环**：
质检发现哪个字段漂了 → 下一轮锚定 Prompt 就强化那个字段。这是三级锚定第 3 级的数据来源。

## 4. 质检 Prompt 设计要点

```
[系统角色] 你是漫剧生产流水线的质检员，判定关键帧是否可用于成片。

[注入] 角色特征库（该镜头出镜角色的 anchor_prompt 全文）
[注入] 分镜要求（景别、构图、动作、台词）
[注入] 同场景已合格帧（作为色彩/画风基准，图像输入）
[输入] 待判定的关键帧（图像）

[判定规则]
- 逐项比对角色特征库，漂移即扣分，指出具体漂移字段
- 与基准帧比对色调/光照/画风
- 景别与构图须符合分镜要求
- 违规元素一票否决，输出 blocked

[硬约束]
- 只依据可见画面判定，不推测、不脑补画面外内容
- 不确定时降低 confidence 并输出 manual，不要猜 pass
- 严格输出 JSON，schema 如下：{...}
```

**三个关键设计**：

1. **注入基准帧而非只给文字描述**——色彩断层和画风漂移必须靠视觉比对判定，
   纯文字描述判不出来。这是多模态视觉模型存在的意义。
2. **"不确定就转人工"**——防止模型为了给出答案而强行判 pass。
   与农牧项目"不将 Prompt 作为安全边界"是同一思路：不信任模型的自信。
3. **证据约束**——只依据可见画面判定。农牧项目里对应的是"将联网资料、本地记录与模型推断区分处理"。

## 5. 黄金测试集与校准（这是 2026 JD 明写的要求）

> 行业要求原文："落地关键能力：完整的 Trace 系统（记录决策与生成细节）、
> 黄金测试集（200+组人工标注问答对）、错误分类体系（按幻觉、答非所问等维度归类驱动优化）"

### 5.1 怎么攒（不花钱）

**关键**：黄金测试集不需要额外调 API 生成素材，**从正式抽卡的副产物里攒**。

第一周做角色锚定实验时，本来就要抽几百张图。这些图连同质检判定结果全部落库，
然后**人工标注**其中的 50-100 张（覆盖各维度不合格类型 + 合格样本），就是黄金测试集。

标注要刻意保证分布：
- 合格帧 30%
- 五官畸形 20%
- 人设漂移 25%（重点，这是最难判的）
- 色彩断层 10%
- 构图问题 10%
- 合规问题 5%

标注脚本：`backend/scripts/label_golden_set.py`（读 `render_attempts`，
逐张展示 + 打标 → 写 `qc_golden_set`）。

### 5.2 校准指标

```
                人工标注
              pass    reject
质检 pass      TP       FN  ← 漏放废片，最危险（浪费后续视频生成钱）
质检 reject    FP       TN  ← 误杀好帧，浪费重抽钱

准确率 = (TP+TN)/总数
召回率 = TP/(TP+FN)          ← 重点：合格帧的识别率
误杀率 = FP/(FP+TN)          ← 重点：直接对应浪费的重抽成本
```

**两个指标的业务含义完全不同，要分开讲**：
- **漏放（FN）成本高**：废片流到视频层，1.4 元/5 秒白花，还污染成片
- **误杀（FP）成本高**：好帧被重抽，0.25 元/张白花，还拉低成功率统计

所以策略上应该**偏保守**（宁可误杀不可漏放），但要量化这个取舍：
> "我的质检 Agent 召回率 X%、误杀率 Y%。我刻意把阈值调保守，因为漏放一张废片到视频层的损失
> 是误杀一张的 5.6 倍（1.4 元 vs 0.25 元）。"

这句话有数字、有权衡、有业务依据——比"我做了质检 Agent"强一个量级。

### 5.3 错误分类体系

不合格样本按维度归类，统计各维度占比，**反向驱动优化**：

```
若"人设漂移"占比最高 → 说明锚定强度不够 → 加强第 1/2 级锚定
若"五官畸形"占比最高 → 说明模型/参数问题 → 换供应商或调 CFG
若"色彩断层"占比最高 → 说明场景批次策略问题 → 同场景集中生成
```

这就是行业说的"错误分类体系驱动优化"，而且你能拿出真实的占比数据。

## 6. Trace 系统

每次质检判定都要能回溯：

```
attempt_id → qc_reports.raw_response（模型原始返回）
           → api_call_logs（调用参数、耗时、花费）
           → render_attempts.request_payload（生成时的完整参数）
           → characters.anchor_prompt + anchor_version（当时用的锚定版本）
```

**能回答的问题**（面试官会问）：
- "这张废片当时用的什么 Prompt、什么种子、什么模型？" → `request_payload`
- "为什么判它人设漂移？" → `dimensions.identity_drift.note` + `drifted_fields`
- "当时的角色锚定是哪个版本？" → `anchor_version`
- "这次判定花了多少钱、多久？" → `api_call_logs`

`anchor_version` 是关键设计：锚定 Prompt 会变，**必须记录判定当时用的是哪一版**，
否则前后数据不可比，优化效果无法归因。

## 7. 最终产出的量化指标（简历 bullet 的数据源）

跑完必须能填出这几个数：

| 指标 | 怎么算 | 简历怎么写 |
| --- | --- | --- |
| 抽卡成功率提升 | 一次过率：引入质检+锚定 vs 盲抽基线 | "首帧合格率从 X% 提升到 Y%" |
| 单镜头平均成本 | `SUM(cost_cents)/COUNT(DISTINCT shot_id)` | "单镜头平均成本降至 Z 元" |
| 质检 Agent 准确率 | 黄金测试集混淆矩阵 | "N 张标注集上召回率 X%、误杀率 Y%" |
| 拦截的无效重抽 | 质检判 reject 且人工复核确认的次数 × 单价 | "累计拦截 N 次无效生成，节省 M 元" |
| 各供应商对比 | `api_call_logs` 按 provider 聚合成功率与单价 | "基于实测数据建立多供应商路由策略" |

**盲抽基线怎么来**：第一周先用"无锚定 + 无质检"跑一批（比如 100 张），
统计一次过率作为对照组。没有对照组，"提升"就是空话。
这批基线数据本身也进黄金测试集，不浪费。

> ⚠️ 诚实提醒：如果最终数字不理想（比如成功率只从 15% 提到 25%），
> **照样写真实数字**。有对照、有方法、有归因分析的 25%，比编造的 80% 强得多——
> 面试官要的是你的工程判断力，不是一个漂亮数字。编数字一旦被追问"怎么测的"就崩，
> 而且会连累你真做过、经得起查的农牧项目。
