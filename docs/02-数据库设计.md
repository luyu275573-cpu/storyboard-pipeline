# 02 · 数据库设计

MySQL 8，`utf8mb4` / `utf8mb4_0900_ai_ci`。主键统一 `CHAR(36)`（UUID），
时间戳统一 `TIMESTAMP DEFAULT CURRENT_TIMESTAMP` + `ON UPDATE`。

## 表清单

| 表 | 作用 | 关键索引 |
| --- | --- | --- |
| `projects` | 项目（一部漫剧/一集） | `status`, `created_at` |
| `characters` | 角色档案（三级锚定第 1 级） | `project_id`, UNIQUE(`project_id`,`name`) |
| `character_refs` | 角色基准图（第 2 级） | `character_id` |
| `scenes` | 场景 | `project_id`, `seq` |
| `shots` | 分镜镜头（流水线最小工作单元） | `scene_id`, `status`, UNIQUE(`scene_id`,`seq`) |
| `render_attempts` | 每次抽卡尝试 ★核心 | `shot_id`, `status`, UNIQUE(`shot_id`,`attempt_no`) |
| `qc_reports` | 质检判定报告 ★核心 | `attempt_id`, `verdict` |
| `qc_golden_set` | 黄金测试集（人工标注） | UNIQUE(`asset_key`), `label` |
| `api_call_logs` | 逐次 API 调用记账 ★核心 | `provider`,`model`,`created_at` |
| `budget_ledger` | 预算与花费汇总 | `project_id`, UNIQUE(`project_id`,`scope`) |
| `pipeline_runs` | 流水线运行实例（断点续跑） | `project_id`, `status` |
| `review_gates` | 人机关卡记录（A/B/C） | `run_id`, `gate_type` |
| `exports` | 成片导出记录 | `project_id` |

★ = 简历量化指标的数据来源，第一周必须打通。

## 核心表结构

### characters — 角色特征库（禁止主观词）

```sql
CREATE TABLE characters (
  id CHAR(36) PRIMARY KEY,
  project_id CHAR(36) NOT NULL,
  name VARCHAR(80) NOT NULL,
  -- 三级锚定第 1 级：结构化特征，生成时原样复用，不允许"清秀/帅气"等主观词
  face_features JSON NOT NULL COMMENT '脸型/眼距/眼型/鼻型/嘴型/痣或疤痕',
  hair_features JSON NOT NULL COMMENT '发色/长度/发型/纹理',
  body_features JSON NOT NULL COMMENT '身高/体型/肩宽',
  outfit_features JSON NOT NULL COMMENT '服饰款式/材质/配件/配色',
  style_lock JSON NOT NULL COMMENT '画风锁定：日系/国潮等 + 全局色调 + 负面提示词',
  anchor_prompt TEXT NOT NULL COMMENT '由上述字段固化生成的锚定描述，版本化',
  anchor_version INT UNSIGNED NOT NULL DEFAULT 1,
  created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE KEY uq_characters_project_name (project_id, name)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

`anchor_prompt` 由特征字段**程序化拼装**并版本号递增，不靠人手写——
保证"每次生成复用完全相同的描述"，这是跨集不崩脸的前提。

### shots — 分镜镜头

```sql
CREATE TABLE shots (
  id CHAR(36) PRIMARY KEY,
  scene_id CHAR(36) NOT NULL,
  seq INT UNSIGNED NOT NULL,
  shot_size VARCHAR(20) NOT NULL COMMENT '景别：特写/近景/中景/全景/远景',
  camera_move VARCHAR(40) NULL COMMENT '运镜：推/拉/摇/移/固定',
  composition TEXT NOT NULL COMMENT '构图描述',
  character_ids JSON NOT NULL COMMENT '出镜角色 ID 列表',
  action_text TEXT NOT NULL COMMENT '角色动作',
  dialogue TEXT NULL COMMENT '台词',
  duration_ms INT UNSIGNED NOT NULL DEFAULT 5000,
  negative_prompt TEXT NULL,
  -- 时序特征递延（第 3 级）：上一合格帧作为本镜头参考
  prev_locked_attempt_id CHAR(36) NULL,
  status VARCHAR(20) NOT NULL DEFAULT 'pending'
    COMMENT 'pending/storyboarded/rendering/qc/review/video/synthesized/failed/suspended',
  retry_count INT UNSIGNED NOT NULL DEFAULT 0,
  max_retry INT UNSIGNED NOT NULL DEFAULT 6,
  locked_attempt_id CHAR(36) NULL COMMENT '人工终审放行的那张帧',
  version INT UNSIGNED NOT NULL DEFAULT 1 COMMENT '乐观锁，防并发覆盖',
  created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE KEY uq_shots_scene_seq (scene_id, seq),
  KEY idx_shots_status (status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### render_attempts — 每次抽卡（成本与成功率的原始数据）

```sql
CREATE TABLE render_attempts (
  id CHAR(36) PRIMARY KEY,
  shot_id CHAR(36) NOT NULL,
  attempt_no INT UNSIGNED NOT NULL COMMENT '第几次抽卡，从 1 起',
  stage VARCHAR(20) NOT NULL DEFAULT 'image' COMMENT 'image/video',
  provider VARCHAR(40) NOT NULL,
  model VARCHAR(80) NOT NULL,
  seed VARCHAR(80) NULL,
  request_payload JSON NOT NULL COMMENT '实际发送的参数，便于复现',
  asset_path VARCHAR(500) NULL,
  asset_sha256 CHAR(64) NULL COMMENT '内容指纹，幂等与去重',
  status VARCHAR(20) NOT NULL DEFAULT 'pending'
    COMMENT 'pending/running/succeeded/failed/timeout/canceled',
  error_code VARCHAR(60) NULL,
  cost_cents INT UNSIGNED NOT NULL DEFAULT 0 COMMENT '本次花费（分）',
  latency_ms INT UNSIGNED NULL,
  -- 幂等键：防重试重复扣费
  idempotency_key CHAR(64) NOT NULL,
  started_at DATETIME NULL,
  finished_at DATETIME NULL,
  created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uq_attempts_shot_no (shot_id, attempt_no),
  UNIQUE KEY uq_attempts_idempotency (idempotency_key),
  KEY idx_attempts_status (status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

`idempotency_key = sha256(shot_id|attempt_no|model|seed)`，配合唯一索引，
即使 Worker 崩溃重启也不会对同一次抽卡重复调用 API 扣费。

### qc_reports — 质检判定（结构化，可回归）

```sql
CREATE TABLE qc_reports (
  id CHAR(36) PRIMARY KEY,
  attempt_id CHAR(36) NOT NULL,
  model VARCHAR(80) NOT NULL COMMENT '判定用的视觉模型',
  verdict VARCHAR(20) NOT NULL COMMENT 'pass/repairable/reject/blocked',
  dimensions JSON NOT NULL
    COMMENT '{facial_deformity, identity_drift, color_discontinuity, composition, compliance} 各维度得分与说明',
  severity VARCHAR(20) NULL COMMENT 'low/medium/high/critical',
  suggestion VARCHAR(40) NULL COMMENT 'reseed/redraw/strengthen_anchor/manual',
  confidence DECIMAL(4,3) NULL,
  raw_response JSON NULL,
  -- 人工复核：黄金测试集标注与质检 Agent 校准的数据来源
  human_verdict VARCHAR(20) NULL,
  human_note TEXT NULL,
  reviewed_at DATETIME NULL,
  created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  KEY idx_qc_attempt (attempt_id),
  KEY idx_qc_verdict (verdict)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### api_call_logs — 全链路记账

```sql
CREATE TABLE api_call_logs (
  id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  project_id CHAR(36) NULL,
  shot_id CHAR(36) NULL,
  attempt_id CHAR(36) NULL,
  kind VARCHAR(20) NOT NULL COMMENT 'image/video/vision/llm',
  provider VARCHAR(40) NOT NULL,
  model VARCHAR(80) NOT NULL,
  success BOOLEAN NOT NULL,
  cost_cents INT UNSIGNED NOT NULL DEFAULT 0,
  latency_ms INT UNSIGNED NULL,
  error_code VARCHAR(60) NULL,
  is_retry BOOLEAN NOT NULL DEFAULT FALSE,
  created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  KEY idx_calls_project_time (project_id, created_at),
  KEY idx_calls_provider (provider, model, success)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

**失败的调用也要记**（`success=0`）——因为失败的限流/超时同样消耗配额，
且供应商成功率对比是路由策略的依据。

### qc_golden_set — 黄金测试集

```sql
CREATE TABLE qc_golden_set (
  id CHAR(36) PRIMARY KEY,
  asset_key VARCHAR(64) NOT NULL COMMENT '素材内容 sha256，保证可复现',
  asset_path VARCHAR(500) NOT NULL,
  character_id CHAR(36) NULL,
  label VARCHAR(20) NOT NULL COMMENT 'pass/facial_deformity/identity_drift/color/composition/compliance',
  label_detail JSON NULL,
  labeled_by VARCHAR(80) NOT NULL DEFAULT 'manual',
  created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uq_golden_asset (asset_key),
  KEY idx_golden_label (label)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

用 `asset_key`（内容指纹）而非自增 ID 做唯一键，保证同一张图不会被重复标注，
且测试集可跨环境复现。

### budget_ledger — 预算熔断的数据基础

```sql
CREATE TABLE budget_ledger (
  id CHAR(36) PRIMARY KEY,
  project_id CHAR(36) NOT NULL,
  scope VARCHAR(20) NOT NULL COMMENT 'project/shot/kind',
  scope_key VARCHAR(120) NOT NULL COMMENT '镜头 ID 或 image/video/vision/llm',
  budget_cents INT UNSIGNED NOT NULL,
  spent_cents INT UNSIGNED NOT NULL DEFAULT 0,
  updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE KEY uq_budget_scope (project_id, scope, scope_key)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

花费累加用 `UPDATE ... SET spent_cents = spent_cents + ? WHERE ... AND spent_cents + ? <= budget_cents`，
靠**数据库层的条件更新**保证不超支，而不是先查后写（避免并发下超预算）。
Redis 里另存一份热计数用于快速熔断，DB 是最终账本。

### review_gates — 人机关卡（先审后播留痕）

```sql
CREATE TABLE review_gates (
  id CHAR(36) PRIMARY KEY,
  run_id CHAR(36) NOT NULL,
  gate_type VARCHAR(20) NOT NULL COMMENT 'character/storyboard/compliance',
  status VARCHAR(20) NOT NULL DEFAULT 'pending' COMMENT 'pending/approved/rejected',
  reviewer VARCHAR(80) NULL,
  note TEXT NULL,
  snapshot JSON NULL COMMENT '审核时的内容快照，防事后篡改争议',
  decided_at DATETIME NULL,
  created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  KEY idx_gates_run (run_id, gate_type)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

## Redis 键设计

| 键 | 类型 | 用途 | TTL |
| --- | --- | --- | --- |
| `run:{run_id}:state` | Hash | LangGraph 状态，断点续跑 | 7 天 |
| `run:{run_id}:progress` | Hash | SSE 进度推送源 | 24 小时 |
| `budget:hot:{project_id}` | String(int) | 预算热计数，快速熔断 | 与项目同寿 |
| `idem:{idempotency_key}` | String | 调用幂等，防重复扣费 | 24 小时 |
| `sem:{provider}` | String(int) | 供应商并发闸门（信号量） | 60 秒自动释放 |
| `lock:shot:{shot_id}` | String | 镜头级互斥，防并发抽卡 | 30 秒 |

**并发闸门必须带 TTL 自动释放**——否则 Worker 崩溃会永久占住信号量，
后续任务全部卡死，这是最容易踩的坑。
