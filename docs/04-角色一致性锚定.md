# 04 · 角色一致性锚定（三级体系）

漫剧和普通 AI 短片的根本区别：它要**连载、多格、角色跨集不崩脸**。
所以角色一致性不是锦上添花，是这个品类的生死线，也是纯调 API 的人做不到的工程活。

---

## 三级锚定体系

| 级别 | 手段 | 解决的问题 | 成本 |
| --- | --- | --- | --- |
| 第 1 级 | 全局特征库固化 | 描述漂移（每次写得不一样） | 零（纯工程） |
| 第 2 级 | 参考图主体绑定 | 语义描述无法精确传达长相 | 低（供应商能力） |
| 第 3 级 | 时序特征递延 | 同场景相邻镜头风格跳变 | 低（复用已合格帧） |

三级是**递进兜底**关系：第 1 级是地基，第 2 级补精度，第 3 级补连续性。

---

## 第 1 级：全局特征库固化

### 核心原则：结构化字段 → 程序化拼装，禁止手写 Prompt

**为什么不能手写**：人手写会不自觉地每次换措辞，"黑色长发"这次写"及腰黑长直"、
下次写"乌黑秀发"，模型就把它们当不同角色。一致性要求**逐字节相同的描述**。

```python
# characters 表存结构化字段
face_features   = {"脸型": "鹅蛋脸", "眼距": "标准", "眼型": "丹凤眼",
                   "鼻型": "小巧挺直", "嘴型": "薄唇", "标记": "左眼下泪痣"}
hair_features   = {"发色": "#1A1A1A 纯黑", "长度": "及腰", "发型": "低马尾", "纹理": "顺滑"}
outfit_features = {"款式": "改良汉服交领", "材质": "亚麻", "配件": "银色发簪",
                   "配色": "月白主色 + 靛蓝滚边"}
style_lock      = {"画风": "日系厚涂", "全局色调": "低饱和冷色",
                   "负面提示词": "3D渲染, 塑料感, 欧美脸, 多余手指, 模糊"}

# 程序化拼装，版本化存储
anchor_prompt = build_anchor_prompt(character)   # 见 app/knowledge/anchor.py
characters.anchor_version += 1                    # 每次特征变更递增
```

### 三条硬规则

1. **禁用主观形容词**：不写"清秀""帅气""温柔""美丽"——这些词模型的解释每次都不同。
   只写可验证的客观特征：脸型、眼距、发色色号、服饰款式与配色。
2. **发色用色号**：写 `#1A1A1A 纯黑` 而非"黑色"，因为"黑色"在厚涂画风下会偏棕偏蓝。
3. **负面提示词全局固定**：存在 `style_lock` 里，所有镜头共用，保证画风收敛。

### 锚定强度可调（质检反馈驱动）

质检 Agent 返回 `drifted_fields: ["hair_color"]` 时，下一轮自动**只强化漂移的字段**：

```
第 1 轮：常规锚定
第 2 轮：漂移字段前置 + 重复强调 + 提高参考图权重
第 3 轮：追加负面提示词（如"棕发, 黑发以外发色"）+ 换供应商
第 4 轮：转人工，检查基准图本身是否有歧义
```

这就是 `render_attempts.attempt_no` 与 `qc_reports.dimensions.identity_drift.drifted_fields`
联动的价值——**锚定策略是被质检数据驱动的，不是拍脑袋调的**。

## 第 2 级：参考图主体绑定

### 基准图要求

`character_refs` 表存角色基准图，需覆盖：
- 正面半身（主基准，必选）
- 侧面半身（转头镜头用）
- 全身（远景/全景用）
- 表情包（喜怒哀惊，近景特写用）

**基准图本身也要过质检**——如果基准图就有畸形，后面全崩。这是第一周要做的第一件事。

### 供应商能力映射

| 供应商 | 能力 | 适用 |
| --- | --- | --- |
| Vidu 参考生图 | 支持 0-14 张参考图，多主体分别锁定 | **多角色同框**（专项强项） |
| 即梦 智能参考 3.0 | 主体迁移、身份绑定 | 单角色，性价比高 |
| 可灵 图像 | 自由多参考图 | 动作镜头 |

**多角色同框必须用支持多主体分别绑定的供应商**（Vidu），
否则两个角色会互相污染特征——这是漫剧最常见的崩脸原因。

### 参数固化

同一角色的所有镜头，除"场景与动作变量"外，其余参数**必须完全一致**：
参考图权重、CFG/引导强度、采样器、画风 LoRA（若有）、分辨率、负面提示词。
这些全部存进 `render_attempts.request_payload`，保证可复现。

## 第 3 级：时序特征递延

### 同场景集中生成

**策略**：不按镜头序号顺序生成，而是**按场景分组批量生成**。

理由：同场景的光照、色调、背景元素应当一致。集中生成时，
第一张合格帧立即成为该场景的**色彩/画风基准**，后续帧拿它做参考输入。
如果按序号跨场景穿插生成，每张都要重新建立基准，色彩断层率会显著上升。

```
❌ 错误：shot1(场景A) → shot2(场景B) → shot3(场景A) → shot4(场景B)
✅ 正确：场景A[shot1, shot3, shot5] → 场景B[shot2, shot4, shot6]
```

### 递延传递

`shots.prev_locked_attempt_id` 指向**上一合格帧**，生成时作为额外参考图输入：

```
场景内第 1 镜头：参考 = 角色基准图 + 场景背景基准
场景内第 N 镜头：参考 = 角色基准图 + 第 N-1 镜头的合格帧
```

这样色调、光照、角色状态在场景内自然连续，不会跳变。

### 与质检的联动

质检的"色彩断层"维度，比对基准就是**同场景已合格帧**（见 `docs/03`）。
所以递延链一旦断裂（某镜头一直不合格），后续镜头的色彩基准也会受影响——
这也是为什么要有 `max_retry` 后转人工，不能让一个镜头卡死整条链。

---

## 实施顺序（第一周）

1. 建 `characters` / `character_refs` 表与 CRUD
2. 实现 `build_anchor_prompt()` 程序化拼装 + 版本号
3. 做 1 个主角的基准图（正面/侧面/全身/表情），**人工过质检**
4. 用同一角色跑 20 张不同场景/动作，人工统计崩脸率 → **这是锚定效果的第一个真实数据**
5. 加第 3 级递延，再跑 20 张对比 → 有对照组才能说"提升了多少"

> 第 4、5 步的对比数据，是简历上"角色跨集一致性"这句话的唯一支撑。
> 没有对照组的"我做了一致性锚定"，等于没说。
