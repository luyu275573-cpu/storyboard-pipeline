# 05 · 预算与成本控制

**总预算：200 元以内。周期：1-2 周。**

这一章不是附录，是架构约束的来源——预算熔断、成本记账、质检放图像层，

## 2. 预算分配（200 元）

| 阶段 | 用途 | 预算 | 预计产出 |
| --- | --- | --- | --- |
| 第 1 周 | 角色基准图 + 锚定实验 | **40 元** | 1 主角基准图集 + 40 张锚定对比数据 |
| 第 1 周 | 盲抽基线（对照组） | **25 元** | 100 张无锚定无质检样本，算出基线成功率 |
| 第 1 周 | 质检 Agent 校准 | **35 元** | 150 张带质检判定，标注 50-100 张黄金集 |
| 第 2 周 | 完整流水线跑通（图像） | **40 元** | 1-2 集完整关键帧，含重抽 |
| 第 2 周 | 视频层链路验证 | **40 元** | 约 80-140 秒视频，1 个完整样例片 |
| — | 机动预备金 | **20 元** | 供应商切换、参数重试 |
| **合计** | | **200 元** | |

**图像层占 140 元（70%），视频层仅 40 元（20%）**——这就是"质检战场放图像层"的预算体现。

### 为什么必须留盲抽基线的 25 元

没有对照组，"我把成功率从 15% 提到 X%"就是空话。
15% 是行业公开数据，不是**你的**基线——你的画风、你的角色、你的 Prompt 风格，基线可能完全不同。
花 25 元买 100 张盲抽样本，才能说出"在我的场景下，盲抽一次过率是 A%，
加了三级锚定是 B%，再加质检重抽是 C%"。这三段对比才是真数据。

而且这 100 张盲抽样本**同时进黄金测试集**（里面有大量不合格样本，正是标注需要的），一分钱不浪费。

## 3. 预算熔断设计

### 三层预算

```
项目级预算（200 元）
  └─ 镜头级预算（每镜头上限，如 3 元）
       └─ 单次调用（单价）
```

任一层触顶即熔断，不等下一层。

### 熔断实现：数据库条件更新，不是先查后写

```sql
-- ✅ 正确：原子条件更新，并发安全
UPDATE budget_ledger
   SET spent_cents = spent_cents + :cost
 WHERE project_id = :pid AND scope = 'project' AND scope_key = 'total'
   AND spent_cents + :cost <= budget_cents;
-- 影响行数 = 0 → 预算不足，拒绝本次调用

-- ❌ 错误：先 SELECT 再 UPDATE，并发下会超支
```

Redis 里另存热计数用于**调用前快速拒绝**（省一次 DB 往返），DB 是最终账本。
两者不一致时以 DB 为准，并告警。

### 重试上限

`shots.max_retry = 6`，超限 → `status = 'suspended'`，**停止自动重试，转人工**。

为什么是 6：按 15% 一次过率算，6 次内至少一张合格的概率约 `1 - 0.85^6 ≈ 62%`；
配合质检的选择性重抽（只重抽不合格的），实际成功率会显著高于盲抽。
超过 6 次说明问题不在运气（可能是锚定本身有缺陷、或分镜描述不可实现），
继续抽是纯烧钱，必须人工介入。

### 预算耗尽的降级策略

预算不足时**不是直接停摆**，而是降级：
1. 降低分辨率（1080P → 720P）
2. 切换到更便宜的供应商（即梦 Pro → 即梦标准）
3. 减少每镜头抽卡张数（N → 1）
4. 暂停视频层，只完成图像层
5. 全部耗尽 → 挂起，保留已有成果

**部分结果保留**是硬要求：预算耗尽时已合格的帧绝不能丢，
这与农牧项目"中断后的部分结果保留"、YumeShelf"执行预算"是同一套思路。

## 4. 成本记账的粒度

`api_call_logs` 记**每一次**调用，包括失败的：

```
成功：cost_cents = 实际单价 × 用量
失败：cost_cents = 0，但 error_code 必填
限流：is_retry = true，记录退避次数
```

**失败也要记**的两个理由：
1. 失败同样消耗配额（多数供应商按"成功才计费"，但限流额度是共享的）
2. 供应商成功率对比是路由策略的依据——如果某家限流严重，实际可用性低于单价优势

### 能算出的报表

```sql
-- 单镜头平均成本
SELECT shot_id, SUM(cost_cents)/100 AS yuan, COUNT(*) AS attempts
  FROM api_call_logs WHERE project_id = ? GROUP BY shot_id;

-- 各供应商成功率与单价
SELECT provider, model,
       AVG(success) AS success_rate,
       AVG(CASE WHEN success THEN cost_cents END) AS avg_cost,
       AVG(latency_ms) AS avg_latency
  FROM api_call_logs GROUP BY provider, model;

-- 质检拦截的无效重抽（= 省下的钱）
SELECT COUNT(*) AS blocked, SUM(140) AS saved_cents  -- 140 = 视频层单次均价（分）
  FROM qc_reports WHERE verdict IN ('reject','blocked');
```

最后一条是简历上"累计拦截 N 次无效生成，节省 M 元"的数据源。
逻辑要讲清楚：**质检在图像层拦住一张废片，就等于省下它流到视频层的 1.4 元**——
这是"质检放图像层"这个架构决策的直接经济价值，能算出具体金额。

## 5. 省钱的具体手段（按性价比排序）

1. **先薅免费额度**：即梦 200 次体验额度、混元/百炼百万 Token，够跑完质检校准
2. **质检用免费额度的视觉模型**，不要用付费图像模型做判定
3. **同场景集中生成**，减少色彩基准重建，直接降低重抽率
4. **锚定强度递进**，不要一上来就用最贵的参考图方案
5. **720P 起步**，只在最终样例片用高分辨率
6. **幂等键防重复扣费**——Worker 崩溃重启时，这条能救命
7. **本地缓存已生成素材**（`asset_sha256` 去重），同参数不重复调用

---

## 6. 超支预警

- 花费达预算 **70%** → 日志 WARN + SSE 推前端提醒
- 达 **90%** → 自动降级到最低成本策略
- 达 **100%** → 熔断，挂起所有待执行任务，保留已有成果

**不要等到 100% 才发现**——这是成本审计必须在第一周就打通的原因，
不能留到最后补。
