# 06 · 实施里程碑（两周）

起始日：**2026-09-23**（周三）。目标：10 月上旬可投递。

> 前提认知：Codex 能帮你快速写代码，但这个项目的瓶颈**不在写代码**。
> 真正的耗时是"抽卡 → 等渲染 → 看结果 → 调锚定 → 再抽卡"这个循环，
> 每轮要等云端排队和渲染，还要烧钱。AI 加速不了这个循环。
> 所以下面的计划把**等待时间**和**编码时间**错开安排。

### Day 3 · 盲抽基线（对照组，不可省）

### Day 4-5 · 三级锚定 + 对比实验

### Day 6-7 · 质检 Agent（核心）

## 风险与应对

| 风险 | 概率 | 应对 |
| --- | --- | --- |
| 供应商限流严重（免费档并发=1） | 高 | 提前排队设计；用 Redis 信号量而非直接失败 |
| 角色一致性调不出来 | 中 | 简化角色设计（避开复杂服饰/多配件）；先保证单角色 |
| 视频层预算不够 | 中 | 只做 1 个 30 秒样例；或降级为纯图像层交付（漫剧本质是"动态漫"，静态分镜+运镜也能讲） |
| 质检 Agent 准确率不理想 | 中 | **照样写真实数字 + 归因分析**，这反而是加分项 |
| 时间不够 | 中 | 砍视频层，保图像层与质检——核心卖点在质检，不在成片 |

**最低可交付线**（如果时间/预算告急）：
角色三级锚定 + 图像层质检 Agent + 黄金测试集指标 + 成本审计 + 盲抽对照数据。
**没有视频层也能撑起一个完整项目条目**，因为卖点是流水线工程与质量控制，不是成片画质。

## 每日节奏建议

抽卡是等待型任务，别干等：

```
上午：提交一批抽卡任务 → 等待期间写代码/文档
下午：收结果 → 人工标注 → 调锚定参数 → 提交下一批
```

**每天早上先看昨天的花费**，超预算立即降级，不要等到最后发现钱烧完了。
