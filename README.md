AI 漫剧**生产流水线的工程与质量控制层**。

不做一个"输入剧本、输出视频"的生成工具（那是即梦、可灵、纳米漫剧流水线的赛道），
而是解决漫剧工业化生产中最贵、最失控的一环：**黑盒抽卡导致的品质失控与成本浪费**。

> 行业基准：图片与视频的平均抽卡成功率仅 **15%**，甚至催生了"职业抽卡师"。
> 本项目把质检与重试从人工经验变成**可编程、可度量、可回归**的工程系统。

## 一、这个项目解决什么问题

漫剧链路：`剧本 → 分镜 → 图像关键帧 → 图生视频 → 合成成片`。

痛点不在"能不能生成"，而在三处：

| 痛点 | 现状 | 本项目的对策 |
| --- | --- | --- |
| 抽卡失控 | 成功率 15%，靠人工肉眼筛、反复重抽 | 质检 Agent 自动判定 + 不合格自动重渲染 + 成本熔断 |
| 角色崩脸 | 跨集、跨镜头人设漂移，画风不统一 | 角色三级一致性锚定 + 资产库固化 |
| 成本不可见 | 钱花在哪个镜头、浪费在哪个环节，说不清 | 全链路成本审计，逐镜头逐次调用记账 |

**核心设计取舍：质检战场放在图像层，而非视频层。**

理由：抽卡成本的大头浪费在图像返工上；而质检 Agent 要判定的问题
（五官畸形、人设漂移、色彩断层）在**静态关键帧上即可判定**，不需要等视频生成。
图像单价约为视频的 1/50，同样的预算能在图像层跑上千次抽卡，得到有统计意义的成功率数据。
视频层只做链路验证与端到端样例，不做大规模抽卡。

## 二、能力边界（明确不做什么）

**做**：
- 角色资产库与三级一致性锚定
- 剧本 → 分镜脚本（结构化 JSON）→ 图像关键帧批量抽卡
- 质检 Agent（多模态视觉模型判定 + 黄金测试集校准 + 自动重渲染）
- 异步任务编排：状态机、断点续跑、失败重试上限、预算熔断
- 全链路成本审计与抽卡成功率统计
- 视频层链路验证（少量调用）+ FFmpeg 时间轴合成
- "先审后播"合规节点（人工审核为强制关卡）

**不做**：
- 不训练任何模型（6GB 显存跑不动 Wan2.2 级别的开源视频模型，全部走云 API）
- 不做剧本创作助手、配音、字幕、剪辑等完整创作平台功能
- 不做多租户 SaaS、计费系统、C 端账号体系
- 不追求成片画质与商业产品对标，追求**流水线的工程质量与可度量性**

## 三、技术栈

| 层 | 选型 | 说明 |
| --- | --- | --- |
| Web 框架 | FastAPI | 原生 async，适配分钟级长任务与 SSE 进度推送 |
| 编排 | LangGraph | 流水线状态图：节点路由、循环重试、断点续跑、人机协同 |
| 任务队列 | ARQ（Redis） | 轻量、原生 async，比 Celery 更贴 FastAPI 生态 |
| 数据库 | MySQL 8 | 项目/分镜/任务/成本账目 |
| 缓存与队列 | Redis | 任务队列、进度状态、幂等键、预算计数器 |
| 存储 | 本地文件系统 | 关键帧、视频片段、成片（生产可换对象存储） |
| 视频合成 | FFmpeg | 按时间轴拼接、转场、导出 |
| 部署 | 腾讯云 + Nginx + systemd | 复用农牧项目的部署范式 |

**模型 API**（按镜头类型路由，全部支持降级）：

| 用途 | 首选 | 备选 | 选择依据 |
| --- | --- | --- | --- |
| 图像生成 | 即梦 3.0 系列 | 阿里云百炼 / 腾讯混元 | 单价低、角色参考图能力强，有免费额度 |
| 角色一致性 | Vidu 参考生图 | 即梦智能参考 | Vidu 多主体角色一致性为专项强项 |
| 质检判定 | 多模态视觉模型 | — | 判定五官畸形/人设漂移/色彩断层 |
| 分镜脚本 | 通义千问 / DeepSeek | 腾讯混元 | 结构化 JSON 输出，有百万级免费 Token 额度 |
| 视频生成 | 可灵 3.0 | 即梦 3.0 720P | 可灵单价低（约 0.64 元/秒），物理运动表现稳 |
